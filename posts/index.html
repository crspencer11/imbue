Title: Building a lightweight agent investigation workflow with mngr

I spent some time evaluating mngr from Imbue as an external developer this week and ended up building a small debugging/investigation workflow around it.
The initial trigger was actually onboarding friction. After install, running:
mngr create
immediately failed with a thread/runtime error.

Rather than manually debugging everything, I built a lightweight workflow that:
  • extracts structured signals from logs
  • searches repository context
  • surfaces likely debugging paths
  • generates concise investigation summaries
What became interesting to me wasn’t the agent itself, but the abstraction model underneath:
  • tools
  • workflows
  • persistent execution context
  • composable debugging/investigation steps
The experience made me think a lot about developer UX for agent systems beyond just prompt interfaces.
I think there’s a particularly interesting opportunity around:
  • reusable workflows
  • shareable debugging/investigation skills
  • structured first-agent onboarding
  • runtime diagnostics for external developers
